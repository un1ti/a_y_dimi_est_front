# RAG Research Analyzer

Локальный сайт для просмотра научных публикаций, конфигураций RAG и результатов экспериментов. В комплект входят десять демонстрационных записей с иллюстративными PDF. Значения этих примеров предназначены для проверки интерфейса.

## Запуск в VS Code

1. Выберите **Файл → Открыть папку** и откройте папку `rag-research-analyzer`.
2. При установленном Node.js 18 или новее нажмите **F5**. VS Code запустит сервер и откроет сайт.
3. Для запуска в терминале выполните `node server.mjs` и откройте [локальный сайт](http://127.0.0.1:4173). Остановка сервера в терминале — Ctrl+C.

На Node.js 22.13 и новее сайт использует встроенный драйвер SQLite. Для Node.js 18 или 20 сначала выполните `npm install` в папке сайта, чтобы установить драйвер `better-sqlite3`. Статические ресурсы, иконки и PDF.js входят в проект. Порт можно переопределить через переменную окружения `PORT`.

## Работа с публикациями

- В обзоре выберите публикацию. Вкладки содержат аннотацию, конфигурацию RAG и результаты.
- Во вкладке «Исследования» выберите условия поиска. Галочки в таблице позволяют сравнить несколько экспериментов. Таблица сравнения помечает строки с разными условиями.
- В анализе публикации нажмите на номер страницы у метрики или на значок источника у поля конфигурации. Просмотрщик перейдёт к указанной странице. Если в текстовом слое найдена точная цитата, она будет подсвечена.
- Кнопка «Проверить» проверяет заполнение связей, номера страниц, границы долей и процентов, параметры фрагментов. JSON сохраняет структуру карточки и замечания. CSV содержит по одной строке на результат.
- «Загрузить PDF» сохраняет оригинал в `database/uploads/`. Карточки, метрики, источники и коллекции хранятся в `database/research.sqlite`. Библиотека доступна из любого браузера, подключённого к этому экземпляру сайта. Для резервной копии остановите сайт и скопируйте всю папку `database/`.
- При первом запуске сервер создаёт базу из схемы SQLI и добавляет десять демонстрационных публикаций. Старые загрузки из IndexedDB автоматически не переносятся. Для переноса конкретного документа загрузите его PDF в новую библиотеку. Переменная `RAG_LIBRARY_DIR` задаёт другой путь к папке базы и загрузок.

## Локальный Scientific Arbitrator v2.5

На этом компьютере окружение уже подготовлено. На новом компьютере установите Python 3.11 или 3.12 и выполните из папки сайта в PowerShell:

```powershell
cd Scientific_Arbitrator_FULL_BACKEND_v2.5_FRONTEND_HANDOFF/backend
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd ../..
```

Запустите сайт через F5. Выберите «Загрузить PDF», затем «Анализировать». Node.js запустит FastAPI на свободном локальном порту и дождётся результата задания. В карточке появятся записи, режим извлечения, оценка готовности к сравнению и ссылки на страницы. Ядро использует рабочую папку `backend/.data`, а сайт сохраняет карточку, доказательства и отчёт о качестве в SQLite библиотеки.

PDF обрабатывается локально ядром Scientific Arbitrator v2.5. Сначала ядро извлекает результаты из таблиц, а при отсутствии подходящей таблицы ищет поддерживаемые параметры и метрики в тексте по встроенным правилам. Для анализа нужен текстовый слой PDF. По умолчанию ядро принимает до 120 страниц. Кнопка «Повторить анализ» запускает это же ядро для ранее сохранённого файла.

### Формат результата

```json
{
  "title": "Example RAG evaluation",
  "authors": "Example Research Group",
  "year": 2024,
  "kind": "Научная статья",
  "abstract": "Краткое описание исследования.",
  "task": "QA",
  "datasets": ["NQ"],
  "protocol": "Held-out test split",
  "config": { "top_k": 5, "top_k_unit": "chunks", "chunk_size": 512, "chunk_overlap": 50, "chunk_unit": "tokens", "model": "Example LLM", "variant": "Стандартный RAG" },
  "evidence": { "top_k": { "page": 2, "fragment": "Top-k: 5" } },
  "metrics": [{
    "id": "m1", "experiment_id": "exp1", "config_id": "cfg1",
    "task": "QA", "dataset": "NQ", "protocol": "Held-out test split",
    "name": "Recall@5", "raw": "89.0", "unit": "%", "value": 0.89,
    "page": 3, "fragment": "Recall@5 = 89.0%", "origin": "primary"
  }]
}
```

Обязательные поля ответа — `title`, `datasets` и `metrics`. Пустые массивы допустимы. У каждой метрики обязательны имя `name` и исходное значение `raw`. Нумерация страниц начинается с 1. `unit` содержит исходную единицу, `value` — нормализованное число. Для долей и процентов нормализованная шкала — от 0 до 1. При отсутствии `value` пересчёт выполняется только для известных единиц `fraction` и `%`. Поля происхождения и протокола сохраняются на уровне каждой метрики. Данные со спорными значениями остаются доступными в карточке.

В конфигурации поле `chunk_unit` задаёт единицу размера и перекрытия фрагментов (`tokens`, `characters`, `words` или `bytes`). Поле `top_k_unit` уточняет, что возвращает поиск, например `chunks` или `documents`. Для иных метрик сервис может указать единицу нормализованного значения в `normalized_unit`.

## Файлы

- `server.mjs`, `analysis-adapter.mjs` — локальный сервер и передача PDF в Scientific Arbitrator v2.5.
- `public/app.js`, `ui.js`, `pages.js`, `styles.css` — навигация, экраны и оформление.
- `public/data.js` — локальное хранение, приём результата и правила проверки.
- `public/viewer.js` — просмотр PDF и подсветка цитат.
- `public/examples/` — демонстрационные PDF и связанные записи.
- `public/vendor/` — PDF.js, ресурсы отображения и лицензии.
